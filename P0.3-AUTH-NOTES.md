# P0.3 — Auth + confirm on destructive actions (implemented 2026-11-14)

Implements the spec's P0.3 item (`~/workspace/meridian-rebuild-spec.md`):
server-side auth + CSRF on destructive actions, fail-closed scheduled
endpoints, preview-before-execute for recalibrations, a server-side confirm
step for Close & Liquidate, and hiding test portfolios from the production
switcher. Working copy only — **nothing was pushed, deployed, or traded
against a live broker** (all verification used the repo's fake Alpaca /
Firestore harness).

## What changed

### `web_ui.py`
- **Admin login (`_admin_token`, `login_route`, `logout_route`, `LOGIN_PAGE`)**
  — One shared admin token: the existing `recalibrate-token` Secret Manager
  secret (the same token Cloud Scheduler already sends), with an env
  override `MERIDIAN_ADMIN_TOKEN` for local dev/tests. `GET/POST /login`
  compares the submitted token in constant time; on success the session is
  marked `admin_authenticated` and the CSRF token is rotated. The token is
  never stored in the session or rendered into a page. No token configured
  → login always fails. `POST /logout` clears the session.
  `app.secret_key` is set from `MERIDIAN_SESSION_SECRET` or a random
  per-process value (sessions don't survive a restart without it).
- **CSRF (`_csrf_token`, `_check_csrf`, `_require_admin_csrf`)** — per-session
  token, exposed to templates as the `{{ csrf_token() }}` Jinja global and
  rendered as a hidden field in every destructive form. `_require_admin_csrf`
  gates a route: signed-in session first, then the CSRF token; either failure
  → `403` and nothing happens.
- **Gated routes** — `POST /execute`, `POST /portfolios/<id>/recalibrate`,
  `POST /portfolios/<id>/close`, `POST /portfolios/<id>/news_watch` all
  require admin session + CSRF. Read routes (`GET /`, `/portfolios`,
  `/portfolios/<id>`, `/stock/<symbol>`, `/simulate`, `/evaluation`,
  `/about`, `/chat`, `/recommend_stream`) are unchanged and stay public.
- **Preview-before-execute (`recalibrate_portfolio(..., dry_run=True)`,
  `RECALIBRATE_PREVIEW_PAGE`)** — the first `POST /recalibrate` computes the
  real plan (live prices, recommendation, pre-trade review) but places no
  orders and writes no ledger entry, and renders the plan with its review
  grade/vetoes. Only a second submission with `confirm=1` (same session +
  fresh CSRF token) trades. Note: the confirming submission **re-derives**
  the plan, so the preview is a snapshot — prices/weights can shift
  slightly between preview and confirm, and the preview run itself warms
  the strategist memory (see test_proactive_recal SCENARIO O).
- **Close & Liquidate, two server-side steps (`CLOSE_CONFIRM_PAGE`)** —
  the first `POST /close` only renders a confirm page listing the holdings
  to be sold; only a second submission typing the portfolio's **exact name**
  (`confirm_name`) sells anything. The JS `confirm()` dialogs remain as a
  courtesy layer only.
- **Fail closed (`_recalibrate_token`, `recalibrate_due_route`,
  `proactive_check_route`)** — when the recalibrate-token secret is unset,
  both scheduled endpoints now return `503` and log an `ALERT`, with or
  without a token header. The old "no secret = run unprotected" opt-out is
  gone. A wrong header still returns `403`.
- **Test portfolios hidden (`_is_test_portfolio`, `_portfolio_selector`)** —
  the switcher hides portfolios flagged `is_test`, named exactly `test`, or
  ending in `-test` (so `Oct2-actual-test` is hidden). Deliberately not a
  bare `"test"` substring: that would also hide `Test PF` or `Latest`.
  Nothing is deleted; test portfolios stay reachable by direct URL.
- **Nav** — `TOP_NAV` shows `🔐 Sign in` when signed out, `✓ Signed in`
  when signed in (via an `admin_signed_in` context processor).

### `daytrade_ui.py`
- `POST /daytrade/halt` now requires the shared day-trade token, like
  resume/lessons already did (the halt form gained a token field when a
  token is configured). `_authorized()` now **fails closed**: no token
  configured → every token-gated day-trade action is refused, instead of
  running unprotected. This also affects resume/lessons, which shared the
  same helper — previously they were open whenever the secret was unset.
  Docstrings updated (the old "halt is open because it only reduces risk"
  reasoning is retired: an open halt button is a denial-of-service on the
  strategy).

## Review fixes (2026-11-15)

Three problems found in review, fixed before deploying:

1. **Session key shared across instances.** Cloud Run runs up to 20 instances, and
   a cookie signed with one instance's random key is unreadable on another, so
   sign-ins failed at random and every deploy signed the owner out. The key now
   comes from the `session-secret` secret (or `MERIDIAN_SESSION_SECRET`); random
   only if neither exists, with an alert. Cookies are HttpOnly, SameSite=Lax, and
   Secure on Cloud Run.
2. **Separate admin credential, rate-limited.** Sign-in uses its own `admin-token`
   secret, not the scheduler's `recalibrate-token`, so guessing or leaking the
   one a person types can't run the scheduled trading endpoints, and vice versa.
   5 failed attempts per client in 15 minutes, or 30 in total, returns 429.
3. **Transient secret errors don't lock out scheduled trading.** A failed Secret
   Manager read is no longer cached for the life of the instance; it's retried
   after 60 seconds. While unreadable the endpoints still fail closed (503).

Not addressed here (follow-ups): the public `/recommend_stream` can change the
cached recommendation that "Launch" buys; the recalibration preview re-runs the
recommendation instead of executing the previewed plan.

## How to configure

| Setting | Where | Notes |
|---|---|---|
| Admin token | Secret Manager secret `admin-token` (project `meridian-508414`) | NEW. Long random value; not the scheduler's token. |
| Session signing key | Secret Manager secret `session-secret` | NEW. Long random value; the same for every instance. |
| Scheduler token | Secret Manager secret `recalibrate-token` | Already exists; must match the scheduler job headers. |
| Admin token (local/dev) | Env `MERIDIAN_ADMIN_TOKEN` | Overrides the secret; convenient for local runs and tests. |
| Session signing key (local/dev) | Env `MERIDIAN_SESSION_SECRET` | Overrides the secret. |
| Day-trade token | Secret Manager secret `daytrade-token` | Already exists; now required for halt as well as resume/lessons. |

No new dependencies (Flask's built-in sessions only). `Dockerfile` needs no
change — both edited files were already in its `COPY` lists.

```
python test_p0_3_auth.py        # new: 9 checks, all P0.3 behaviours
python test_portfolio_page_reconcile.py
python test_proactive_recal.py
python test_evaluation.py
python test_portfolio_history.py
python test_stock_count.py
python test_portfolio_reconcile.py
python test_rulebook.py
python test_daytrade.py
```

All of the above pass in this working copy (run 2026-11-14; see the report
for the one test update this forced — see below). Existing tests that posted
to now-protected routes were updated to the new flows via helpers in
`test_portfolio_page_reconcile.py`: `login(c)`, `admin_post(c, url, data)`,
`recalibrate_now(c)` (preview + confirm). `test_proactive_recal.py`
SCENARIO O was updated to assert on both recommendation calls, because the
preview legitimately warms the strategist memory before the confirming run.

Manual (local run — still needs the usual GCP/Alpaca credentials at import):

```
MERIDIAN_ADMIN_TOKEN=<redacted> python web_ui.py   # http://127.0.0.1:5050
```

1. Signed out, `curl -X POST localhost:5050/portfolios/<id>/close` → `403`, nothing sold.
2. Open `/login`, sign in with the admin token → redirected home, nav shows `✓ Signed in`.
3. Portfolio page → "Recalibrate Now" → preview page listing planned trades, no orders placed → "Confirm" → trades execute.
4. "Close & Liquidate" → confirm page → type the wrong name → refused, still open → type the exact name → liquidated.
5. `curl -X POST localhost:5050/portfolios/recalibrate_due` (no header) → `503` when the secret is unset; with the header → runs.
6. Toggle the news watch signed out → `403`.

## Intentionally NOT changed

- Read endpoints stay public (viewing needs no sign-in), per the spec.
- No trading logic, sizing, rulebook, LLM prompts, or data paths touched.
  `recalibrate_portfolio()` gained only a `dry_run` early-return after the
  plan + review are computed; scheduled/proactive callers pass no new
  argument and behave exactly as before.
- No in-app user accounts — single shared admin token, as the spec allowed
  ("simplest one consistent with the existing token approach").
- Cloud Run IAM / the `gcloud run services proxy` tunnel in `open_webapp.sh`
  is unchanged and remains the outer perimeter; this change is the in-app
  layer underneath it. **Live deployment was not tested** — verify on Cloud
  Run that the `recalibrate-token` secret exists and the scheduler headers
  still match, or the scheduled endpoints will now 503 (by design).
- The proactive check's internal recalibrations (news-watch sells) are not
  human-gated — that is P0.4's corroboration work, not this change.
- No real secret values anywhere in code, tests, or this note (tests use the
  stub Secret Manager value `"stub"`).
